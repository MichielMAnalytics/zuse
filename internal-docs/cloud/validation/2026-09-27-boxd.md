## Rollout

Staging Wrangler enables Boxd and references this template. Production contains
the same template metadata but leaves the adapter disabled. Existing default
placement and authentication authority settings remain unchanged.

From the PR checkout, install the staging secret and deploy:

```sh
bun install --frozen-lockfile
cd infra/api
bunx wrangler login
bun run secret:boxd
bun run deploy:staging
```

Enter the Boxd API key at Wrangler's prompt. Then use the staging app's Cloud
settings to build an account image on Boxd, start a new Boxd chat, and verify
agent execution, terminal access, reconnect and resume. These authenticated app
steps and the Cloudflare deployment are not covered by the adapter test and
were not run here because Cloudflare credentials are not configured.

For a later production rollout, install `bun run secret:boxd:production`, enable
`BOXD_ADAPTER_ENABLED` in `wrangler.production.jsonc`, then run:

```sh
ZUSE_CONFIRM_PRODUCTION_API_DEPLOY=deploy-api.zuse.sh bun run deploy:production
```

Boxd has no billing settlement source. The deployment guard rejects enabling it
with cloud billing enforcement, and runtime placement independently excludes it
under enforcement. Do not disable billing enforcement merely to enable Boxd.
